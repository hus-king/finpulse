# FinPulse 服务器部署与访问

服务器：`ssh airhust@airhust.cn -p 11622`。网站部署在服务器上，前端、FastAPI 和 MySQL 都由服务器提供；访问者电脑不需要运行项目或安装 Python、Node、数据库。

## 1. 两种访问方式

### 同一局域网直接访问

浏览器打开 **http://202.114.212.116:8000/**。

服务器物理网卡 `eno1` 的实际地址为 `202.114.212.116/25`，直连网段为 `202.114.212.0/25`。该地址不是 RFC1918 私网地址，网站入口有来源限制。2026-10-06 核对的允许范围如下：

| 服务器看到的来源 | 当前范围 |
| --- | --- |
| `202.114.212.0/25` | 服务器直连网段，通常可用主机为 `.1`～`.126` |
| `10.17.214.75` | 单个地址，来自被 UFW 拦截的访问日志 |
| `10.14.152.145` | 单个地址，来自被 UFW 拦截的访问日志 |
| `127.0.0.1` | 服务器本机，供 SSH 隧道使用 |

两个单独地址的对应人员/设备尚未确认，现有规则是临时排障记录，不应把请求日志当作身份或授权证明。其他校园子网并不自动属于允许范围；新增访问范围需确认来源归属与学校实际网段。服务器看到的来源可能经过网关或代理转换，与电脑显示的地址不同。跨校园子网可先用下面的 SSH 方式。

请求路径：**成员浏览器 → 服务器网卡的 8000 端口 → Nginx → 静态前端或 FastAPI → 本机 MySQL**。Nginx 提供 React 构建文件，`/api/` 请求转到服务器的 `127.0.0.1:8001`。前端调用相对路径 `/api/...`，因此自动使用当前网站地址，不需要在成员电脑填写后端地址或 API 密钥。

### 通过 SSH 隧道访问

在成员自己的电脑终端运行：

```bash
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=15 -o ServerAliveCountMax=3 -L 127.0.0.1:18000:127.0.0.1:8000 airhust@airhust.cn -p 11622
```

然后浏览器打开 **http://localhost:18000/**。保留这个 SSH 连接，按 Ctrl+C 会关闭隧道。若 18000 被占用，换成 18001，并将网址同步改为 `http://localhost:18001/`。

Windows 项目目录中也可运行：

```powershell
.\scripts\web-tunnel.ps1
```

这个脚本只使用系统 OpenSSH 和成员现有的 SSH 配置/认证，不依赖项目 API 密钥、数据库配置或 `.venv`。后台模式仅适用于已经配置 SSH 密钥的成员：

```powershell
.\scripts\web-tunnel.ps1 -Background
```

后台进程 PID 存在 `.runtime/web-tunnel.pid`，错误日志在 `.runtime/web-tunnel.stderr.log`。它不会自动重连；连接断开后重新执行脚本。

这里有两个不同的 `127.0.0.1`：`-L` 左边是成员自己的电脑，右边是 SSH 服务器。请求路径是 **浏览器 → 自己电脑的 18000 端口 → 加密的 SSH 连接 → 服务器的 127.0.0.1:8000 → Nginx → FastAPI/MySQL**。因此，即使电脑不在服务器局域网，只要能正常 SSH 登录，也能访问网站。网页本身仍需登录，SSH 身份和 hsq/szy/zhr/lzk 等网站账号是两套独立认证。

SSH 隧道加密传输；局域网直连本版使用 HTTP。后续面向公网访问时再配置 HTTPS 与域名，不应直接把当前 HTTP 登录入口放开到整个公网。

## 2. 服务器文件与服务

| 路径或服务 | 内容 |
|---|---|
| `/home/airhust/finpulse-deploy/current` | 当前发布目录的符号链接，包含源码、测试、文档和构建后的前端 |
| `/home/airhust/finpulse-deploy/releases/20261006-lan` | 本次发布快照；没有 `.git`，不是供多人直接修改的开发工作区 |
| `/home/airhust/finpulse-deploy/shared/config.local.json` | 私有模型/Tavily/SMTP/MySQL 配置，权限 600，不上传 GitHub |
| `/home/airhust/finpulse-deploy/shared/service.env` | 主机白名单、Cookie、调度开关等运行环境，权限 600 |
| `/home/airhust/finpulse-deploy/shared/.venv` | 在 Linux 上创建的独立 Python 3.12 环境；没有复制 Windows `.venv` |
| `/etc/systemd/system/finpulse.service` | 后端服务，单 worker，故障自动重启，开机启动 |
| `/etc/nginx/sites-available/finpulse-lan` | 两个网站监听地址、局域网来源限制、前端和 API 转发 |
| `/home/airhust/finpulse` | 原有 Git 仓库，保持原样，不被本次发布覆盖 |

MySQL 继续使用已有 `finpulse_dev` 数据库。部署后的后端直接连接 `127.0.0.1:3306`，使用已有应用账号；不再经过开发机的 `13306` SSH 数据库隧道。MySQL 本身仍只监听回环地址。

后端只监听 `127.0.0.1:8001`；Nginx 监听 `127.0.0.1:8000` 和 `202.114.212.116:8000`。局域网入口同时使用 Nginx `allow/deny` 和 UFW 来源限制；UFW 在 `eno1` 上允许上述网段及两个单独地址访问目标 `202.114.212.116:8000`。其他来源仍拒绝，没有新增面向全部公网的 8000 或 MySQL 端口规则，也没有修改原来的 SSH 规则。

数据库、后端和 Nginx 都长期运行，不依赖 tmux 或保留 SSH 管理终端。`finpulse.service` 以普通账号运行，私有配置不通过 Nginx 提供。网页登录使用既有账号，刷新后的 Cookie 会话恢复机制同样有效。

部署配置源文件在仓库 `deploy/` 中。`deploy/requirements.lock` 固定本次已验证的包版本，并补充 Linux 的 AkShare 依赖；后续升级应重新测试，不应随意覆盖运行环境。

## 3. 查看和维护

以下命令在服务器终端运行：

```bash
sudo systemctl status finpulse nginx mysql --no-pager
sudo journalctl -u finpulse -n 50 --no-pager
sudo nginx -t
curl --noproxy '*' http://127.0.0.1:8000/api/health
```

修改后端配置后重启后端：

```bash
sudo systemctl restart finpulse
```

修改 Nginx 配置后检查并重新载入：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

成员继续在本地开发，通过 Git 提交、评审和合并；部署时先在本地构建前端，再把确定版本的源码和 `dist/` 上传到新的 `releases/` 目录，链接私有配置、验证依赖后切换 `current` 并重启服务。保留旧发布目录可供回退。不要把数据库、私有配置或 `.venv` 当作源码同步，也不要直接在正在服务的发布目录共同改代码。

每日晨报调度只在服务器实例开启，本机开发实例关闭。服务器沿用共享数据库中设置的时间、订阅、运行记录及推送去重状态；部署验收不会手动发送测试邮件或微信。

本机完整运行与服务器完整运行可以同时存在，访问本机 `localhost:8000` 或开发前端 5173 会调用本机后端，访问 SSH 隧道 18000 会调用服务器后端。当前开发机的 MySQL 模式共享 `finpulse_dev`，本机调试也会影响共享数据；独立测试应使用 SQLite 或另外约定的测试库。本机源码修改和 GitHub 推送都不自动更新 `current` 发布目录。

## 4. 验证范围

验收记录在本机被 Git 忽略的 `.runtime/server-deploy/`。验证包括 SSH 隧道的完整网站、真实登录/恢复/退出、私人自选与晨报读取、模型请求、Tavily 搜索、AkShare 日线、服务重启恢复以及服务器上的自动化测试。

局域网限制使用服务器实际网卡地址发起请求验证允许，用非允许来源地址验证拒绝。这能验证网站监听和来源限制，不能代替另一台校园局域网设备的端到端测试；当前开发电脑不在 `202.114.212.0/25`，因此仍需一台该网段设备打开局域网网址，确认学校网络没有额外隔离。

后续排障在 UFW 日志发现 `10.17.214.75`、`10.14.152.145` 的 8000 端口请求，原白名单范围过窄导致丢弃。已在 Nginx 和 UFW 同时追加单独规则，Nginx 配置检查通过，原允许地址仍 HTTP 200，其他来源仍 HTTP 403。但尚未确认这两台设备真实访问成功，不能写成整个校园网已验收。

2026-10-06 实测结果：服务器 Linux 环境 90 项测试通过；本机两个相关测试组共 22 项通过。SSH 隧道网站、健康检查、7 天 Cookie、登录恢复与退出、私人自选/订阅/历史晨报/预览均通过；真实模型返回成功（本轮约 1.3 秒），Tavily 返回 2 条搜索结果，AkShare 返回 21 条日线。服务器网卡地址 HTTP 200，非允许来源 HTTP 403。服务重启后 Cookie 会话仍有效。调度仅服务器开启，下一次为北京时间 2026-10-07 08:30，本轮没有手动测试推送。

Linux 首轮测试有两处等待时序断言失败：并发任务仅等待 1 秒、任务在内存标为结束后尚未完成最终落库。已改为有截止时间地等待任务完整收尾，功能断言保持不变，重新执行全部测试通过。没有为了通过测试跳过鉴权、并发隔离或重复采集检查。
