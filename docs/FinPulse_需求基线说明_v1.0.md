## 7 需求变更声明与技术细化

本版没有对实验 1 产品需求作实质变更，因此不另附一份宣称“已变更需求”的材料。原要求没有删除、放宽、重编号或将目标降格为已实现；设计文档第 14.1 节与本声明一致。尚未采纳中性/拒判评分、严格 168 小时时窗等提议，相关影响已在设计第 14.3 节说明。

接口兼容新增字段、拟新增任务结果接口和 409 冲突响应属于明确写出的技术设计变化，不是当前接口事实。它们仍需要实施和兼容测试；在实现后应更新 API 契约版本和验证记录。以下逐项列出与需求关联的补缺，不使用“需求未改”掩盖接口行为变化。

| 设计差距编号 | 原实现边界 | 拟补充机制 | 影响的原需求 |
| --- | --- | --- | --- |
| G01 | 不同参数任务可能读取同一最新看板；同账号请求可能复用不同参数的活动任务 | 绑定run及不可变snapshot；拟加I04R与409参数冲突 | FR10/FR11/FR18，NF02/NF07 |
| G02 | 普通任务强制中断后可能遗留running，不自动续做 | 按实例对账标failed，保留研判供用户重试 | FR10，NF04 |
| G03 | 自选与任务分写，当前依靠执行门和补偿 | 拟改同事务保存，提交后启动 | FR03/FR10，NF02/NF04 |
| G04 | 综合分0的展示状态可能被理解为待研判 | 区分多空抵消与暂无评分，单条仍禁止0 | FR11，NF06；保留BR05 |
| G05 | 日期晨报/latest分写；发送未知状态需明确交互 | 拟事务保存与指针对账，未知不自动重发 | FR14/FR16，NF04 |
| G06 | 逻辑工作并发不等于外部HTTP并发；没有B1实测 | 拟增加每源计数、限流和监测后进行压测 | NF01/NF03/NF08 |

新增 M、I、II、D、UI、P、F、ADR、V、G、A 均为设计标识，不进入实验 1 需求编号序列。C 表示静态核对到当前代码，P 表示待实现方案，T 表示待验收目标。代码存在、结构校验通过、模拟样例达到阈值均不能代替业务验收。
