# 新闻事实与公司传导：证据编号开发试验

本轮完成一个独立的离线两阶段标注版本和可读复核页。实际试跑发现并修复了重复输入、并发预算和配对编号兼容问题；主体别名与语义标签质量仍然阻碍数据准入。**没有重训、没有生产接入、没有新增人工金标，C 不自动删除新闻。**

## 新流程

1. 按新闻抽取事实，不给该阶段目标公司背景。区分公司事件、行业信号、宏观信号及未知，并记录价格、供需、技术、监管、合同等类型和提议、受理、获批、实施等阶段。
2. 冻结新闻事实后，逐公司检查自身事件与每条事实的业务传导。新闻的行业信号是否存在，不因目标无关而被改成不存在。不同事实各自记录投入成本、销售价格、双向、非价格或未知角色，不把同篇新闻的多个机制压成一个标签。

引用改为从给定证据编号中选择，由程序解析原文字段与坐标。不同材料和公司使用不同编号空间；表格标题、单位与数据保留。多段证据分别显示，不伪造一段拼接引文。

坐标单位为 Python Unicode codepoint，对应 `title + 正文 + 表格行` 的完整可见串，**不是原 PDF 的页面坐标**。公司证据来自现有背景字段，其原始 PDF 页码与逐字引文映射保留在背景元数据中；字段位置的校验不证明背景或传导的语义正确。

## 实际执行与故障

所有材料来自已见 v8 历史开发归档，保留原 split 和保守事件家族；未引入独立测试。配对按产品和传导对照预先列出，不按已有 DeepSeek 标签挑选。仍只有七家公司背景，药品公告缺同业制药公司的困难负例。原料价格与行业统计不等于收益预测标签。

### 输入膨胀与预算

第一轮在第二阶段重复发送完整可见串、证据文本和已解析引文，并在两个目标间再次复制；大表格一次 prompt 达约 95,460 token。实际 971,833 token 超过 700,000 的旧软阈值。这是本轮发现的实现问题，原始失败记录保留。

修复后的请求共享新闻与冻结事实，只携带一份证据文本，已解析引文留在本地，不在请求中重复。所有目标按相同文章分批，防止共享错误的事实。增加派发前的 UTF-8 字节保守上界，加最大输出及 4,096 token 包络余量；并发请求占用预留，无法获得 usage 时保持占用，进程恢复不返还未知消耗。该上界针对所声明的字节分词聊天端点，未将其宣传为通用计费工具。

### 配对编号与缓存

第二轮模型返回 `600031` 等目标代码而非 `article_id__600031`，完整原答仍保存。最终版本显式发送 `pair_id` 并要求逐字复制；兼容规则仅在**本次请求内代码唯一且完全相等**时映射，并保留 `returned_id` 与 `id_normalization`。截短、重复、缺失、其他新闻 ID 或外部代码继续拒绝。

v9b 回放单独冻结原输入、抽取阶段、原始回答和当前校验代码的摘要。按预留请求号顺序选首个结构有效响应，否则保留首个失败；没有按语义挑答案。它是开发时发现问题后的派生重验，**原轮次的零覆盖不改写，不升级为独立评估**。

阶段 A 完成后冻结输出，阶段 B 绑定该摘要。输入、提示、预算、运行代码变化必须另建实验；缓存结果本身也保存摘要，恢复拒绝重复 ID 或被修改的回答。结构失败是终态复核项；相同零温度提示不反复重标。请求及包络失败受每输入两次预留约束。

最终代码审查还指出 ticker 前缀、ASCII 名称前缀及代码/配对 ID 碰撞三个边界；当前工具更新为合同 v3.1，新增拒绝检查与回归例。没有重跑或覆盖冻结的 v9c；另存 16 条结果的开发重验，结构状态变化为 0，新增请求为 0。中文名称的字面出现仍不是实体消歧证明，须审稿及来源别名登记。

## 当前仍待解决的质量问题

- 最小试跑的恒瑞主提示有公司事件未给主体证据，整篇抽取保持失败；另一个提示使用公司正式名称，而背景仅有简称，因此自身 YES 被拦下。不能凭字符串包含关系放过；下一步需要绑定官方来源的正式名称、证券简称和母子关系证据。
- 原料价格试例中，螺纹钢上涨与工程机械“钢材”投入可以形成待验证的成本机制，但实际采购品种与占比未知。回放显示这类条件传导可以明确保留，不能因此声称完成了真实影响判断。
- 公告可能同时含新审批、历史竞品获批和产品背景；目前未独立建模 `当前事件/历史背景` 及事实发生时间。公告日期不能替代每条事实的时间。
- 价格角色目前通过枚举、事实类型及业务引文的结构检查；所选业务是否真正证明投入或销售暴露，仍需语义审稿。
- 公司背景仍是来源支持的 AI 选摘，`human_verified=false`；本轮未扩展公司池、补齐所有缺正文来源或确认独立事件家族。

因此仍关闭训练准入。固定 v6 模型、旧 v7/v8 结果及前瞻声明保持原状；旧 v8 **724 个归档文件逐一 SHA256 校验无变化**。

模块不被 FastAPI 导入。实验材料、原始回答和私有配置不提交 Git。

```sh
python -m experiments.news_processing.evidence_pipeline NEW_ROOT \
  --prepare-from .runtime/news-expansion-v8-20261012 \
  --source-ids 42f9fb274bb70db6ee68 7402da85cd47550de5d9

python -m experiments.news_processing.evidence_review NEW_ROOT
```

```sh

```

验证：新增 **33 项**测试覆盖 Unicode/CRLF、表格、外部证据、空事实、主体冲突、外国合作方代码、名称/代码前缀与碰撞、完整事实链接、请求预算、未知费用预留、共享 payload、缓存篡改、截断、失败保留、派生回放与 HTML 文本转义；完整后端 **421 项测试通过**。v9c 实际恢复新增请求为 0。

## 后续顺序

1. 从官方公告和背景报告建立有证据的主体别名/母子关系登记，区分新事件与历史背景；以开发错误做规则与提示修复，继续保留失败材料。
2. 优先审稿原料成本、售价、竞争与地区资格等不同机制，补同业/较远/无关对照公司；人工核心与其他提供商的盲审弱标签分别保存，不把 AI 回放签成金标。
3. 补正文和业务暴露，复核事件家族，再按冻结的数据准入条件决定是否重训。
4. 候选版本固定后另行预先声明未见来源与未来时间窗评估。当前开发材料不重新称为独立测试；继续影子评估，C 不自动删除新闻。
