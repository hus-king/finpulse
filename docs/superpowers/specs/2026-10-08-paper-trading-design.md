# FinPulse A 股模拟盘设计

日期：2026-10-08。状态：用户已确认设计；尚未开始产品代码实现。

## 用户目标与已确认范围

为软件工程作业增加可在现有服务器访问的模拟盘。用户已选择接近真实 A 股的规则，并确认第一版采用最新有效行情即时模拟成交，初始资金为每个账号 **20 万元**。

成功标准：登录后能查看独立模拟账户，搜索沪深股票，在允许的交易时段买卖，看到资金、持仓、可卖数量和盈亏变化；刷新页面或重启服务后保留数据。当天买入的股份不能当天卖出。功能沿用现有深浅主题和手机布局，完成验证后同步 GitHub 并部署到 http://202.114.212.116:8000。

## 第一版体验

主导航增加“模拟盘”。未登录显示登录入口；登录后展示：

- 账户概览：总资产、可用现金、持仓市值、累计盈亏及收益率；另展示已实现和未实现盈亏。
- 买卖面板：独立股票搜索、买入／卖出切换、股数输入、可买／可卖数量、最新报价及时间、预估金额与费用、提交结果。
- 持仓：股票名称与代码、总数量、可卖数量、当日锁定数量、含买入费用的平均成本、估值价格及时间、市值和浮动盈亏。点击持仓可选中该股票。
- 成交记录：时间、方向、股票、数量、成交价、金额、分项费用和成交后的现金余额；支持加载更早记录。
- 简明规则说明：20 万虚拟资金、T+1、交易时段、板块数量规则、模拟费用和报价来源。

金额和价格默认保留两位小数，股数为整数，红涨绿跌。休市、行情获取中、延迟和请求失败有明确提示；无有效报价时禁用提交。股票搜索仅选择交易标的，不自动加入自选股，不触发新闻或 AI 付费采集。

页面显式标注“虚拟资金 · 模拟成交”。已有分钟行情不是逐笔实时报价，成交按有效分钟价格模拟；不承诺复现真实市场成交、流动性或滑点。

## 交易规则

### 账户与资金

每个登录账号初始现金为 20,000,000 分，初始持仓和成交记录为空。采用首次成功成交时在同一事务内创建账户的方式；尚未成交的账户读接口返回上述初始状态，不在 GET 请求中写入资金。

不提供充值、提现、杠杆、卖空、账户重置或真实券商接入。20 万元是预算，不能保证可以买入任意股票的最小申报数量；不足时显示原因。

### 时间与 T+1

后端使用 Asia/Shanghai 和现有核验交易日历。第一版仅在交易日 **09:30 ≤ 时间 < 11:30、13:00 ≤ 时间 < 14:57** 接受即时模拟成交。集合竞价和盘后交易不在第一版范围。午休、周末、节假日和未经核验的日历年份禁止新成交；仍可查看账户及历史记录。

每次买入记录交易日期和数量。同日买入数量锁定；在后续已核验交易日变为可卖。卖出先扣除较早买入的可卖批次，不能动用当天买入的股份。不通过定时任务解锁，按查询或提交时的交易日期计算，避免服务停机影响 T+1。

### 股票与申报数量

仅支持现有股票库中核验的沪深 A 股；不接受客户端自造股票或价格。按代码识别主板、创业板和科创板，存托凭证等不属于本版支持品种。

- 主板、创业板：买入为 100 股整数倍。卖出正常按 100 股整数倍；若可卖余额含不足 100 股的零股，可以保留该零股，或一次卖完该零股部分并保留整手余额，不能拆分零股。
- 科创板：普通买卖至少 200 股，之后可按 1 股递增；可卖余额不足 200 股时只允许全部卖出该可卖余额。
- 即时模拟申报上限采用对应市价申报数量上限：主板 100 万股、创业板 15 万股、科创板 5 万股。所有申报同时受现金与可卖数量限制。
- 当持仓同时含可卖和当日锁定股份时，数量例外仅针对可卖余额，不允许突破 T+1。

停牌状态不能仅凭存在历史价格判定可交易；无新鲜有效分钟行情时不成交。第一版不单独模拟涨跌停排队、集合竞价撮合、部分成交、限价挂单、撤单、公司行动、分红或投资者适当性门槛。

### 价格与费用

成交价格只取服务器的未复权 1 分钟行情缓存，转换为人民币分，四舍五入到分。至少同时满足：价格有限且大于零；来源状态正常且无采集错误；报价日期为当前交易日；分钟时间距服务器时钟不超过 180 秒；采集成功时间距当前不超过 90 秒。分钟条可能以结束时间标记，允许其时间最多领先 60 秒；采集时间不得领先服务器时钟。其余情况拒绝成交并提示等待刷新，不能改用昨日收盘价执行交易。

下单之前或报价读取时，可调用现有分钟行情服务安排刷新；不在资金事务中等待外部网络请求。事务内重新读取报价和当前时间，再次检查时段与新鲜度。

使用固定模拟费率，不代表用户实际券商收费：双向佣金为成交金额的 0.03%，每笔最低 5 元；双向过户费为成交金额的 0.001%；卖出另收成交金额的 0.05% 印花税。佣金包含本版模拟的经手等费用，不重复另计。各项单独四舍五入到分，并保存在成交记录中。

买入扣除股款及全部费用；卖出增加扣除费用后的款项。所有持久化金额使用整数分，计算费率用 Decimal 和 ROUND_HALF_UP，不使用浮点数累积现金。

## 盈亏与估值

持仓保存总数量、剩余成本金额、买入日期批次以及最近成交价格。买入成本包含股款和买入费用；多次买入累加数量与成本。卖出按卖出前的持仓平均成本分摊剩余成本，四舍五入到分；最后清仓时扣尽残余成本，避免累计舍入残差。

- 已实现盈亏 = 卖出净收入 − 分摊的持仓成本，累计保存。
- 未实现盈亏 = 当前估值市值 − 剩余成本。
- 总资产 = 现金 + 持仓估值市值。
- 累计盈亏 = 总资产 − 初始 20 万元；收益率以 20 万元为分母。

估值允许使用最近有效分钟价格，即使当前已休市或报价较旧，但每只持仓明确显示时间与延迟状态。若分钟缓存缺失，用该持仓最近成交价估算并标注“按成交价估算”；绝不把缺失报价当零元。成交仍必须满足更严格的新鲜度条件。第一版不展示缺少完整基准的“今日盈亏”。

账户读取利用已有行情缓存，刷新选中标的沿用现有分钟行情服务的并发和重试限制。估值时间较旧时提示刷新，不伪装成实时估值。

## 后端与存储

新增独立 paper_trading 业务模块、持久化模块和 API 路由；在 app 生命周期中接入现有身份库、ResearchStore、股票库和分钟行情服务。避免把交易逻辑塞入研究采集模块。

复用现有 research_records 表，不改变服务器 MySQL 表结构或权限：

- namespace=paper_account，record_key=account，owner=用户 ID：账户版本、初始资金、现金、累计已实现盈亏、累计费用、持仓与日期批次、成交序号。
- namespace=paper_trade，record_key=客户端 request_id，owner=用户 ID：不可变的成功成交记录，包含请求指纹、序号、时间、报价依据、全部费用及成交后余额。

不能使用 ResearchStore.get 后再 ResearchStore.put 的独立事务组合来扣款。所有写入必须使用同一个连接和事务。MySQL 锁定该用户行（SELECT ... FOR UPDATE），SQLite 使用现有 BEGIN IMMEDIATE；锁内重新确认账号有效，读取账户和幂等记录，验证规则，更新持仓与现金，插入成交记录，再一起提交。初始化同样受用户行锁保护，避免双请求创建两份资金。读出的账户 JSON 为一次完整快照。

同账号并发提交必须串行结算，不允许负现金、超卖或丢失更新；不同账号数据以 owner 隔离。异常时全部回滚；重试不能造成重复成交。

## API 与身份校验

接口前缀 /api/paper：

- GET /account：当前登录用户账户、持仓估值及市场状态。
- GET /quote/{code}：选中股票报价、板块规则、市场状态和不可成交原因；可安排现有分钟行情刷新。
- GET /trades：当前用户的成交历史，默认 20 条，最多 100 条；按单调递增成交序号倒序，用 before_seq 加载更早记录。
- POST /trades：request_id（UUID）、code、side（buy/sell）、quantity（严格正整数）。不接受 owner、价格、费用或余额。

读接口沿用 current_session，写接口沿用 authorize_model_request 的登录、Origin 和 CSRF 校验。所有账户和交易响应为 Cache-Control: no-store。请求严格拒绝多余字段、布尔数量、非整数数量及未知股票。

相同用户和 request_id 的同内容请求返回第一次成功成交结果，不能重复扣款；不同内容复用 request_id 返回冲突。成功记录重放优先于交易时段及行情校验，因此网络丢失后的重试在收盘后也能取得原结果；账号有效性仍需检查。失败请求不写成交记录。

错误使用稳定业务码和中文说明，区分休市、日历待更新、报价过期、申报数量错误、现金不足、T+1 限制、持仓不足和幂等冲突。响应不泄露数据库细节或其他用户信息。

## 前端组织与请求安全

新增 PaperTradingPanel 及独立类型／格式化辅助文件，在 App 主导航和标题接入；新增独立样式，使用现有主题变量和交互组件。

账户组件按用户 ID 挂载，退出登录或切换账号时清空账户状态；搜索和报价请求在切换股票时取消，防止旧响应覆盖当前标的。预估费用只用于展示，成交以后端结果为准。

提交期间禁用重复点击；同一提交在不确定网络结果后重试沿用原 request_id，不生成第二笔交易。确认成功后刷新账户与成交记录，不通过前端乐观扣款。输入改动形成新的交易意图时使用新 request_id，并提示未知结果先刷新记录核对。

小屏幕采用纵向表单和可滚动持仓／成交表格；键盘操作、表单标签、错误提示和状态反馈保持可访问。

## 验证与部署

验证重点：20 万初始化及账号隔离；买入、卖出、费用与分摊精度；当天禁售及下一交易日解锁；午休、收盘、周末、节假日和未知日历；各板块数量和零股；无效／过期／未来报价；资金不足与超卖；重复请求及冲突；并发与事务回滚；登录、Origin 和 CSRF；刷新与重启后持久化。

用测试时钟和本地隔离数据库验证真实规则场景，不能在生产中绕过交易时段或使用假行情。运行相关单元／API 测试、现有后端回归测试、前端构建，并用浏览器检查登录入口、账户页、深浅主题、手机布局和提交反馈。

完成后同步 GitHub，打包新发布目录和前端产物，沿用现有共享配置、Python 环境、数据库及 Nginx。切换 current 并重启现有后端服务以加载新增路由，检查站点、健康接口、新接口权限和静态资源。保留前一发布目录；失败时切回并重启恢复。部署前确认服务器当前版本没有被其他开发更新，避免覆盖并行工作。不改变服务的开机启动设置。
