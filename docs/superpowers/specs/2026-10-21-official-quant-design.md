# FinPulse 官方量化策略与模拟盘托管设计

日期：2026-10-21。状态：用户已批准实施，并允许使用空闲 GPU。

## 目标与约束

用户要求使用历史数据开发或改造量化算法，在 `ssh husking194` 上训练，不影响已有进程；接入 FinPulse 模拟盘，让用户选择手动操作或官方算法代操作，并为更多量化算法保留接口。

首版沿用已有沪深 A 股、20 万元模拟账户与交易规则。以下为设计假设：日频择股、只做多、不融资、账户默认手动；用户主动启用后才允许自动交易。目标是交付可复现训练、真实样本外报告和可用的托管链路，收益数值以实测为准。

实际代码仓库为 `/home/kislate/school_project/software/finpulse`，当前聊天工作目录是尚无代码的空仓库。现有后端为 FastAPI，前端 React/TypeScript，交易由 PaperTradingService/PaperStore 处理；账户数据存储在 SQLite/MySQL 的 research_records 中。

## 方案比较与选择

1. 推荐：自有轻量日频多因子策略，以 PyTorch 小型多层感知机回归模型预测未来约 5 个交易日收益，输出组合目标权重。数据、模型、风控和订单执行分层，训练资源较少，便于复现和扩展。
2. 纯规则动量与均线策略：实现和解释简单，作为基准保留，但不能代替用户要求的历史训练和验证。
3. 引入完整量化平台或强化学习框架：依赖和环境成本更高，现阶段不作为默认路线；后续可通过策略适配器接入。

## 数据与训练

- 独立历史行情适配器采集日线，复用 AkShare 来源体系但不把训练数据导入生产账户数据库；不调用收费新闻或大模型接口。
- 首轮限定约 30 只跨行业、交易活跃的沪深 A 股，目标覆盖 2018 年至最近已完成交易日；实际覆盖范围、缺失、上市日期和采集错误写入 manifest。股票池在训练前冻结，报告明确当期样本选择及幸存者偏差，不宣称全市场表现。
- 原始与复权行情分开保存，包含来源、采集时刻、复权口径、日期范围和文件 SHA-256。训练与推理使用同版本、同口径特征；价格按收益率和比值构造，避免把股票绝对价格作为跨股票预测依据。
- 特征包括历史多周期收益、均线偏离、波动率、振幅、成交量变化；只使用信号日已完成的历史数据，不使用当日未收盘日线或事后新闻评分。
- 预测标签为信号日之后下一交易日开始的约 5 日收益；特征、标签和成交时点分别明确，禁止用信号日收盘价实现当日交易。
- 按全体股票共同的交易日期切分，约前 60% 训练、中间 20% 验证、最后 20% 最终测试。边界移除标签跨界样本，滚动验证留出至少标签跨度的间隔；不得逐股票随机打散。预处理仅拟合训练部分，参数只在训练/验证部分选择，测试集仅做最终评估。
- 报告包含数据覆盖、冻结配置、净值、总收益、年化收益、最大回撤、换手、交易数、胜率及明确年化口径的风险调整收益指标，与等权和简单动量基准比较。汇总全部验证结果，不只挑选最好区间。
- 回测按下一交易日可成交价格模拟，使用未复权价格处理整数股、现金和费用，另计双边滑点；T+1、交易数量和停牌/涨跌停限制必须明确处理。不能在已有模拟盘不支持公司行为的情况下把复权价格直接当成交价；首版回测需检测并保守排除公司行为跨越的持仓窗口，报告排除次数和影响，不宣称精确总回报复制。
- 数据覆盖不足、数值异常、模型验证失败时，策略处于不可用状态并显示原因。测试收益为负时照实展示；技术有效性与是否盈利分别报告，不反复调整最终测试集来筛选收益。
- 产物包括模型、特征版本、训练配置、数据清单、依赖版本、校验和及报告。模型加载仅允许本地受信任发布产物，不接受用户上传的 pickle/joblib。

## 模拟盘交互

- 增加“操作方式”：手动、官方日频多因子 v1。策略卡展示版本、历史数据区间、样本外结果、适用股票池和运行状态。
- 用户启用时展示接管当前账户的含义：对现有持仓纳入组合风险计算；不在策略股票池的现有持仓只估值与占用风险额度，不自动清仓。账户存在无法估值持仓时暂停新增风险。
- 用户可随时暂停并恢复手动；切换不自动清仓。切换、暂停和自动下单必须在同一账户锁下核验配置版本，暂停提交成功后旧决策不能再产生新成交。
- 托管时手动新订单由后端拒绝，页面提示先切回手动，避免两个操作者争用资金；已有未确认订单先按原请求号解决，成功请求仍允许幂等重放。
- 页面展示最后决策时间、行情日期、预测/目标权重、执行/跳过原因、下一次检查和错误信息。成交记录标记手动或策略及模型版本，切换前的历史成交继续可读。
- 关闭浏览器后托管继续，由服务器调度；本地开发和测试实例默认关闭调度，不改变共享生产账户。

## 策略扩展接口

新增 `backend/quant/`，分离策略注册、模型适配器、特征、风控、持久化和执行。

统一策略契约：

```text
metadata() -> id, name, version, feature_version, universe, cadence, report
validate_config(config) -> normalized_config
decide(context) -> as_of, target_weights, reasons, model_version
```

context 含已完成行情、账户估值、持仓、时点及受限配置。策略只产生目标权重，不获取数据库写权限，不直接调用交易服务。目标权重须有限、非负且总和不超过 1。新增官方算法通过服务器注册与适配器接入，用户不能提交任意 Python 代码执行。

拟新增接口均沿用现有登录、CSRF、owner 隔离与 no-store 策略：

| 接口 | 用途 |
| --- | --- |
| GET /api/paper/strategies | 可用官方策略、版本、报告概要和不可用原因 |
| GET /api/paper/automation | 当前账户操作方式、配置版本、运行状态 |
| PUT /api/paper/automation | 切换手动/策略或暂停，校验配置版本防止覆盖较新选择 |
| GET /api/paper/automation/decisions | 当前账户决策与执行记录、分页 |

配置、运行状态和决策使用独立 research_records 命名空间，无需初始化或清空现有数据库。成交来源以向后兼容的可选字段扩展。

## 调度、风控与成交

- 默认交易日北京时间 10:00 后检查一次日频信号；仅用上一已完成交易日的日线。服务重启可在当前可交易时段补做当天未完成决策，收盘后不补单。
- 使用数据库租约避免多实例同时执行，执行记录包含 owner、策略版本、配置版本、信号日和确定性请求号。执行前与每笔下单时重新核验租约、账户模式与配置版本。
- 每账户每天一次组合决策，卖出后再买入；单票目标上限 20%、总目标仓位上限 80%、最多 5 只股票，单次调仓成交额上限为可可靠估值净资产的 30%。持仓额度按当前持仓与拟成交后风险核验，不能把每次下单限制当作总仓位限制。
- 首版 15% 的历史峰值回撤触发暂停新增交易并显示原因，不承诺能在 T+1、停牌或行情不可用时立即卖出。峰值估值口径和更新条件固定，不用缺失报价制造误触发。
- 自动订单经现有 PaperTradingService/PaperStore 的事务与规则执行，保留交易日历、交易时段、T+1、整手、现金、费用及新鲜分钟报价校验。策略不得绕过底层规则。
- 自动交易新增可成交检查：未知停牌状态、涨跌停边界、缺少必要数据时跳过；分钟成交仍为产品模拟，无法复现真实盘口排队。数据不足、历史信号过期、数值异常时不生成订单，错误不能伪装成正常空仓信号。
- 推理与行情网络请求在资金事务之外；事务内仅重新校验配置、报价和执行金额。任务取消和服务关闭可恢复，部分成功按已成交结果续做，绝不重复成交；幂等冲突不能自动更换 UUID 重试。
- 有效持仓可卖数量不足、现金不足或调仓额预算不足时记录部分执行原因，剩余目标留到下一决策，不循环下单。
