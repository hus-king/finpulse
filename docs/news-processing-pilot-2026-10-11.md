# 新闻处理拆分流程：历史开发试验

已实现独立研究工具：材料检查 → 公司业务事实 → 公司自身事件/行业传导两题 → 大模型弱参考与条件说明 → 全量影子路由 → 人工复核材料。**本轮没有生成新的微调权重，也没有接入生产过滤。** 原始模型回放证明新题目需要监督训练；数据门槛先挡住了缺类的训练。

## 本轮实际结果

| 项目 | 结果 |
|---|---|
| 材料 | 既有历史材料 19 篇 × 7 公司 = 133 对，12 个事件组；没有新抓取未来评估材料 |
| 新标签 | DeepSeek 两个提示各 133 条；同一服务商的弱参考，不是独立真人真值 |
| 可用弱参考 | 110 对：训练 61、开发验证 27、校准 22 |
| 待复核 | 23 对；全部 133 对仍供真人核验；human_verified=0 |
| 有效标注调用 | 68 次，返回的 total_tokens 合计 255,267 |
| 失败记录 | v5 在 Python3.8 兼容检查失败，没有发请求；v5a 100 次 HTTP 失败；单次诊断确认 HTTP400。失败调用未返回 usage，不推定其计费情况 |
| 原始模型回放 | 固定多语言 Laya 基座、温度 1，133 对全部完成；没有优化权重或拟合温度 |
| 新训练 | 未启动。校准缺 own_event=YES、industry_relation=POSSIBLE；不改标签或事件组来凑支持 |
| 保留策略 | 保留 133，删除 0；114 条建议大模型复核、19 条建议自身事件分析，均只为影子建议 |
| 检查 | 39 项新增测试、309 项完整后端测试通过；5 个旧归档及两份预注册共 509 项文件校验均匹配 |

两个任务分别是：

- own_event：新闻是否有证据证明目标公司自身发生实质事件；YES/NO。
- industry_relation：行业事件是否能传导到具体业务；CLEAR/POSSIBLE/NONE。大模型记录另保留 DIRECT、CONDITIONAL、DISTANT、SENTIMENT、NONE、UNKNOWN，以及新闻引用、业务引用和待证条件。缺材料单独待补，不强制变成 NONE。

原始模型在 **27 对、3 个事件组的开发弱参考**上的结果如下；这不是独立测试，也不能与上一版 ABC 模型直接比较。

| 任务 | 结果 | 暴露的问题 |
|---|---|---|
| 公司自身事件 | 1/27 一致，macro-F1 0.0357 | 27 对都预测 YES，26 条对照公司被误判 |
| 行业关联 | 4/27 一致，macro-F1 0.1879 | 23 条 NONE 中，16 条被判 CLEAR、7 条 POSSIBLE |

因此，拆分题目具有可解释的任务边界，**零样本基座尚不可用作自动路由**。当前概率未校准，0.8 只是开发启发式阈值；建议数量不是准确率。已有 v4b 权重及原冻结未来评估不变，不能替换成这个新任务的回放结果。

## 复核材料与具体缺口

本地完整归档位于工作树 `.runtime/news-processing-v5b-20261011/`：

- `human_review.html`：133 对完整材料、原始表格、业务背景及来源、双提示弱参考、影子模型建议。
- `priority_review_23.html`：23 对优先复核材料。
- `human_review_queue.jsonl`：可追溯复核状态；没有真人签名。
- `dataset_manifest.json`、`training_gate_failed.json`：固定事件组及缺类原因。
- `corpus_expansion_requirements.json`：下轮素材配额、机制与对照公司要求。
- `pilot_preregistration.json`、`base_inference_freeze.json`：教师试验与后续原始模型回放分别在预测前冻结；前者原 13 项文件仍匹配。

发现的两个具体错误说明不能把双提示一致当真值：新华保险财报配三一重工、中远海控时，两个提示都回答 YES；新闻侧身份引用检查挡住了它们。新华保险自身的那对却因改写原始财务表格引用而不合格，导致校准正类缺失。除此之外还有条件/远关联分歧和拼接引文。原始答案保留，不能用字符串相似度放宽规则来“修复”指标。

下轮应增加新的公司自身事件及条件/远关联事件组，覆盖地区项目、产品监管资格、客户/供应商身份、投入价格与利润传导、技术标准与订单、纯板块情绪。每篇配目标公司、同业不同产品、较远上下游、无关行业对照。起步为自身事件和条件关联各增加训练 4 组、验证 2 组、校准 2 组，并由真人核验一批核心标签；长期 1000–3000 对是采样目标，不是达到即可上线的保证。不得移动本轮角色或沿用本轮对进行调参后再称为独立测试。

语义边界核验后再单独声明下一轮训练。后续中文 reranker、直接 DeepSeek 和 Laya 应使用同一材料/事实并比较行业保留与误报；本轮尚未运行 reranker 基准。旧 Oct12–Nov1 前瞻协议没有启动，也没有新材料或新模型预测写入其中。

## 审稿与执行决定

一次独立整分支审查确认 Laya 题目/标签/logits 顺序一致，提出三个重要问题，均用失败测试复现后修复：完整教师来源校验、畸形预测造成整批中断、重启重置单输入重试额度。原始模型适配器是在训练门槛失败后追加的，单独经过标签不泄露、选项排列及不完整输出测试和真实 GPU 回放；没有再宣称它得到第二次独立审稿。

执行决定及代价：

1. v5 兼容/完整表格问题在请求前修正，新建 v5a，原冻结归档保留；代价是一个额外小归档。
2. v5a 的 HTTP400 原样留存，另建 v5b，只加明确 JSON 指令并修复审稿边界；代价是前述 100 次失败请求和 1 次诊断，加上新声明的最多 100 次标注预算，实际成功轮 68 次。总计 169 次 POST，其中 101 次 HTTP 失败。只读 `/models` 查询另一次。官方 JSON 模式要求提示中包含 json；修正后的相同服务模型返回了有效结果。[DeepSeek JSON 模式文档](https://api-docs.deepseek.com/guides/json_mode/)
3. 审稿未判断语义真值、GPU结果、供应商故障及归档/推送；执行阶段保留真人待核验，实测原始 GPU 回放、接口恢复及 509 项旧冻结校验。代价是结果仍仅属开发弱参考，不能承诺泛化性能。
4. Laya 每选项 48-token 上限另用真实分词器检查：实际 18–25 tokens；没有截断。代价是新增一次只读模型检查，没有降低证据标准。
5. 缺类门槛照原声明执行，停止新训练，另冻原始基座回放检验流程；代价是本轮没有新 checkpoint，回放未经校准且误报明显。

无延期的 Minor 审稿项。仅推送研究开发分支，未合入 main、部署网站或开启任何自动过滤。
