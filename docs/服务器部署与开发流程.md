# 服务器部署与开发流程

更新于 2026-10-06。支持本机运行与服务器完整运行，推荐成员在本机开发，服务器提供共同体验的版本。

## 当前运行方式

- 本机完整运行：按 [README 第 2 节](../README.md#2-第一次在-windows-上启动) 安装、配置并运行 `start.ps1`，访问 `http://localhost:8000/`。
- 本机开发：FastAPI 在 8000，Vite 在 5173；具体命令见 [README 第 3 节](../README.md#3-日常开发更新和测试)。
- 服务器运行：`/home/airhust/finpulse-deploy/current` 是发布快照，Nginx + systemd 常驻，FastAPI 在回环 8001，MySQL 在回环 3306。原 Git 工作区 `/home/airhust/finpulse` 保留。
- 体验服务器：来源在白名单内可访问 `http://202.114.212.116:8000/`；能 SSH 登录的成员可转发到本机 18000，具体命令及校园访问范围见 [服务器部署与访问说明](服务器部署与访问说明.md)。

共享 MySQL 模式下，本机和服务器操作会修改同一套数据。独立试验可用模板默认的 SQLite。只有服务器实例开启晨报调度，本机开发关闭。各个电脑上的 8000 端口不会互相冲突。

## 成员从零开始与合作

1. 仅使用网站：获得自己的网页账号，通过允许的网络或已授权的 SSH 隧道访问，无需安装项目依赖。
2. 参与开发：克隆仓库，按 README 安装依赖、复制配置模板，密钥及共享数据库权限由负责人单独提供；它们不在 GitHub。
3. 在本机分支开发、测试、提交，通过评审合并；不在正在运行的发布目录里共同编辑。

```bash
git clone https://github.com/hus-king/finpulse.git
cd finpulse
git switch -c codex/your-change
# 修改并测试后，选择本次需要提交的文件
git add <本次修改的文件>
git commit -m "说明本次修改"
git push -u origin codex/your-change
```

合并后的成员更新使用 `git pull --ff-only origin main`；先提交或暂存本机修改。需要处理分叉时先合并/变基，不用强制推送覆盖其他成员工作。服务器源码与本机源码独立，GitHub 推送不自动部署。

## 发布服务器版本

确认合并版本后，安装该版本依赖、运行测试、构建前端，把确定版本的源码和 `dist/` 发布到新的 `releases/` 目录，使用已有私有配置；验证后切换 `current` 并重启 `finpulse.service`，保留旧版本供回退。运行日志和维护命令见 [服务器部署与访问说明](服务器部署与访问说明.md)。`deploy/` 中有 Nginx、systemd、运行环境模板及固定版本依赖。

更新已有 Git 工作区、安装依赖和构建前端可沿用下方历史记录中的工具路径，但当前网站由发布目录中的 systemd 服务运行，8000 已由 Nginx 占用。构建后还需明确发布；在旧工作区执行 `git pull` 本身不会替换正在运行的网站。

## 手动启动并在本地查看

在本机终端执行以下命令，同时启动服务器程序和本地 SSH 转发：

```bash
ssh -t -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
  -L 127.0.0.1:8000:127.0.0.1:8000 airhust@202.114.212.116 \
  'cd /home/airhust/finpulse && exec .venv/bin/python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000 --workers 1 --no-proxy-headers'
```

浏览器打开：

- 网站：http://127.0.0.1:8000/
- 服务状态：http://127.0.0.1:8000/api/health
- API 文档：http://127.0.0.1:8000/docs

保持终端运行，在该终端按 **Ctrl+C** 停止程序和转发。不要同时重复启动。此方式不安装 systemd 服务、不自动启动、不修改防火墙。

若本机 8000 端口已被其他程序占用，把 `-L` 改为 `-L 127.0.0.1:8001:127.0.0.1:8000`，浏览器改为访问 `http://127.0.0.1:8001/`；服务器端口仍为 8000。

## 本地修改并同步 GitHub

以下命令在本地项目根目录执行。拉取前先提交或暂存尚未提交的修改；提交前检查差异，只包含本次需要同步的文件：

```bash
git pull --ff-only origin main
git status
git diff
git add <本次修改的文件>
git commit -m "说明本次修改"
git push origin main
```

多人同时修改同一功能时，使用各自的分支和 Pull Request 合并；推送冲突时先处理远程新增提交，不强制覆盖。

## 更新服务器代码

推送 GitHub 不会自动部署。先在启动终端按 Ctrl+C 停止网站，再登录服务器，确认没有未提交修改，然后依次执行；任一步失败都应停止，修复后再继续：

```bash
ssh airhust@202.114.212.116
cd /home/airhust/finpulse
git status --short
git pull --ff-only origin main
export PATH="$HOME/.local/share/finpulse-node/node-v22.23.3-linux-x64/bin:$PATH"
npm ci
$HOME/.local/bin/uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
npm run build
exit
```

完成后，重新执行上面的手动启动命令。修改前端后必须重建，浏览器才会显示新页面。更新时保留 `config.local.json` 和数据库，禁止重新执行 `scripts/setup_mysql.py` 初始化已有数据库。

Markdown 课程文档统一保存在 `docs/`，仓库根目录仅保留 `README.md`。
